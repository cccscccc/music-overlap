# 我们的音乐重合度

粘贴两个歌单链接，算出**你们共同喜欢多少首歌**，把重复的歌列出来 ——
还能**直接按顺序播放**这批共同歌曲。

支持 **网易云音乐 / QQ 音乐 / 酷狗音乐**，而且**三家之间可以混着比**
（比如「我的网易云喜欢」对「你的 QQ 音乐歌单」）。

本地小工具，**零第三方依赖**，只在你自己的电脑上运行，不经过任何第三方服务器。

## 它能做什么

- **粘贴链接就出结果**：三家的歌单页面地址、手机分享链接、纯歌单 ID 都认，
  也支持粘**网易云用户主页链接**（会自动去找 TA 的「我喜欢的音乐」）
- **跨平台对比**：两边的歌单可以来自不同平台，靠「歌名 + 歌手」对上
- **显示两个人的昵称和头像**，以及各自歌单的名字和歌曲数
- **共同歌曲带封面**，一眼能认出是哪张专辑
- **每首歌标出它来自哪个平台**，跨平台时还会写出「另一边是哪首歌」
- **四种呈现方式**：列表 / 小图标 / 中图标 / 大图标（像 Windows 文件夹的「查看」那样切换，会记住你的选择）
- **算完自动开播**：对比一完成就自己从第一首能放的歌开始按顺序播，带进度条（可拖动）、上一首 / 下一首 / 暂停 / 音量
- **页面和歌曲渐进出现**，不是一下全砸出来
- **结果摘要就一张卡**：两个人、共同数字、重合度、口径都在同一块里，不重复堆数字
- **该说的限制会主动说**：读不全、口径偏松、被截断，都会在结果上方摆一条提醒
- **搜索过滤 / 复制列表 / 导出 CSV**（CSV 带来源平台、能不能播、原站链接）

## 快速开始

需要 [Node.js](https://nodejs.org/)（18 以上，建议 LTS）。

**Windows**：双击 `启动.bat`，浏览器会自动打开。

**其他系统 / 手动启动**：

```bash
node server.mjs            # 默认 http://127.0.0.1:8787
node server.mjs 9000       # 换端口
```

然后打开 <http://127.0.0.1:8787>，把两边的歌单链接粘进去，点「开始对比」。

## 三个平台各自能做什么

| 平台 | 读歌单 | 听歌 | 备注 |
|---|---|---|---|
| **网易云音乐** | 全量 | ✅ | 支持整份「我喜欢的音乐」；VIP 曲要填登录凭证 |
| **QQ 音乐** | 全量 | ✅ | 需要 `y.qq.com` 的歌单页地址；付费曲拿不到地址 |
| **酷狗音乐** | **只读得到前 30 首** | ❌ | 公开页面就只放 30 首，且播放地址要浏览器行为指纹 |

酷狗那两条是它的接口限制，不是这里偷懒：工具会**如实标出来**（结果上方一条提醒 +
每首歌标「无法试听」+ 「按顺序播放全部」置灰并说明原因），不会假装能播。

## ⚠️ 几条需要知道的限制

**1. 歌单必须是「公开」的。**

平台不允许未登录查看私密歌单。如果对方的「我喜欢的音乐」设成了私密，程序读不到，
页面会明确告诉你「读不到歌单列表」，而不是假装算出个 0。

让对方改一下（30 秒）：网易云 → 我的音乐 → 我喜欢的音乐 → 「···」→ 编辑 → 关掉「私密歌单」。

**2. 有的歌放不出来，这是平台的限制，不是程序的毛病。**

- 网易云 / QQ 的 **VIP、付费、无版权**曲目不向未登录用户提供音频。这类歌在列表里会标上
  「VIP 专享」或「受限」，连播时会自动跳过，不会卡住。
- 如果你自己开了会员，把浏览器里的登录凭证填进页面下方「进阶」区，就能连会员曲一起播。
- **跨平台时还会自动换来源**：同一首歌经常「网易云是 VIP、QQ 却能听」，而默认音源只按平台顺序挑。
  所以首选来源放不出来时，会自动拿 `counterpart` 记的另一边 ID 再试一次（播放器左上角会显示
  实际正在播的是哪个平台），两边都不行才跳过 —— 不会一遇到 VIP 就直接跳。

> 实测样本：某两个公开歌单的 88 首共同歌曲里，26 首可以直接播放 —— 比例因歌单而异，
> 越偏冷门/独立音乐的喜欢列表，能直接播的比例通常越高。
>
> 自动播放会**从第一首能放的歌开始**，中途遇到不能放的直接跳过，不会卡住。

**3. 跨平台的数字天生比同平台「宽」。**

两边不是同一家时，歌曲 ID 体系不同，只能靠「歌名 + 歌手」匹配，比同平台的 ID 精确匹配宽松。
这种情况下结果上方会有一条提醒说明。所以**跨平台的数字不要直接和同平台的数字比**。

## 匹配口径

口径由「两边是不是同一家平台」自动决定：

| 场景 | 判断依据 | 说明 |
|---|---|---|
| **同一平台**（默认口径） | 歌曲 ID 完全相同 | 最准，不会虚高 |
| 同一平台的「疑似同版本」 | 歌名 + 歌手完全相同 | 单独列在「疑似同一首歌（不同版本）」里，不计入大数字 |
| **跨平台** | 歌名 + 歌手完全相同 | 只能如此，结果上方会提示口径偏松 |

音频版本不同（原版 / Acoustic / Live）**不会被算成同一首** —— 录音不一样，算进去会让数字虚高。
**宁可少算，不误算。**

### 两个比例，两个分母

结果卡上并排两个数字，它们回答的是两个不同的问题：

| 显示 | 算式 | 回答的问题 |
|---|---|---|
| **重合度** | 交集 ÷ 较小的那一侧歌单 | 「TA 的歌单，我有几成」 |
| **整体相似度** | 交集 ÷ 并集 | 「两个人合起来，重合的部分占多少」 |

两个比例的分母都**只由真正参与对比的歌**构成。歌单里会有拿不到详情的条目（下架、版权变动），
那些歌既进不了交集，也不该影响分母 —— 否则会算出一个静默偏低的数字，界面上还看不出来。
被排除的数量会单独提醒（「有 N 首拿不到歌曲信息…」），不藏在分母里。

## 实测

**同平台**（两个真实的网易云公开歌单，2206 首 × 620 首）：

- 共同歌曲 **88 首**，用时约 0.5 秒
- **重合度 14.2%**（88 ÷ 620，占较小的那一侧歌单）
- **整体相似度 3.2%**（88 ÷ 2738，交集 ÷ 并集）
- 另有 8 首「同名不同版本」单独列出（88 + 8 = 96）
- 这两个数字和 `_dev/api-check.mjs` 的断言一致。注意它们**只覆盖「ID 相同且都能取到详情」的歌**：
  下架曲会被排除并单独提示，独立重算如果依赖同一个详情接口，同样看不到那些歌。

**跨平台**（同一份网易云歌单 × 某 QQ 音乐歌单 137 首）：共同 11 首，用时约 1.8 秒。
跨平台的并集按「匹配后的候选数」算（`候选A + 候选B − 共同数`），不再拿两边的原始 ID 去比 ——
网易云是数字 ID、QQ 是字母数字 mid，那样比出来的并集恒等于两边之和，比例必然偏低。

## 技术说明

服务端只用 Node 内置模块，**不需要 `npm install`**。用到的都是各家公开接口：

| 平台 | 接口 | 用途 |
|---|---|---|
| 网易云 | `/api/v6/playlist/detail?id=X&n=1` | 歌单元数据 + **全量** `trackIds` + 创建者昵称/头像 |
| 网易云 | `/api/user/playlist?uid=X` | 列出用户歌单，按 `specialType=5` 定位「我喜欢的音乐」 |
| 网易云 | `/api/v3/song/detail?c=[…]` | 批量取歌名 / 歌手 / 专辑 / 封面，200 首一批 |
| 网易云 | `/api/song/enhance/player/url/v1` | 取播放地址（VIP 曲返回 `code: -110`） |
| QQ 音乐 | `c.y.qq.com/qzone/fcg-bin/fcg_ucc_getcdinfo_byids_cp.fcg` | 歌单详情，**带 `song_begin` / `song_num` 翻页**拿全量 |
| QQ 音乐 | `u.y.qq.com/cgi-bin/musicu.fcg` (`vkey.GetVkeyServer`) | 取播放地址（付费曲 `result: 104003`，`purl` 为空） |
| 酷狗 | `www.kugou.com/yy/special/single/{id}.html` | 歌单页内联的 `var data=[…]`，**只有 30 首** |

本工具自己对外提供的接口：

| 接口 | 用途 |
|---|---|
| `GET /api/platforms` | 平台清单与输入提示（前端启动时拉一次） |
| `POST /api/compare` | 对比两个歌单 |
| `POST /api/audio-url` | 批量查询哪些歌能播（按平台分组，用于在列表上标注） |
| `POST /api/cookie` | 提交登录凭证，**只写内存** |
| `GET /api/audio?platform=&sid=` | 音频流代理，**透传 Range**，进度条才能拖动 |

音频为什么要走本地代理：各家的音频地址都有防盗链和跨域限制，直接给 `<audio>` 用会失败；
代理还顺便解决了不暴露登录凭证的问题。

## 发给不懂命令行的人用

```bash
node _dev/build-portable.mjs          # 打包，产物在 dist/
```

打出来的 `dist/音乐重合度-便携版.zip`（约 **34MB**）解压后**双击就能用**：

| 系统 | 怎么启动 | 要不要先装东西 |
| --- | --- | --- |
| Windows | 双击 **启动.bat**（或「打开音乐重合度.lnk」） | **不用**，包里自带 `bin/node.exe` |
| macOS | 双击 **启动.command** | 要装 Node.js 18+ |
| Linux | 终端里 `./启动.sh` | 一般已经有了；没有就 `sudo apt install nodejs` |

三种启动器做的事一样：起本地服务 → 自动开浏览器 → 关掉窗口就停止服务。
Windows 那份在端口被占用时会自己换到 8788 再试一次，并告诉用户为什么。
包里还附了 `先看我.txt`（30 秒说明）。

**为什么 Mac / Linux 那份不能也自带运行时**：便携包里塞的 `bin/node.exe` 是 **Windows 程序**，
在 macOS / Linux 上根本跑不起来；硬要执行只会得到一句 `cannot execute binary file`，
用户完全不知道该怎么办。所以 `启动.sh` 的顺序是「先找包里的 Unix 版 `bin/node`
（只有在那台机器上重新打过包才会有）→ 再退回系统里装的 node → 都没有就说明白该怎么装」。
跨平台交叉打包 exe 目前也不合适：Node 的 SEA 虽然支持指定别的平台的二进制，
但要求关掉 `useCodeCache` / `useSnapshot`，更方便的 `--build-sea` 又要 v25.5+（本机 v24 没有）。

参数：`--no-runtime` 只打程序（约几十 KB，Windows 那边也就需要对方自己装 Node 了）；
`--no-zip` 只铺文件夹不压缩。`dist/` 不进版本库——它是构建产物，随时能重新打出来。

**为什么不打成一个单文件 exe**：那要用 Node 的 SEA 把代码和前端塞进可执行文件，还得处理
Windows 清单（否则可能弹 UAC），改一行代码就得重新构建，出问题也没法让朋友自己看是哪个文件。
现在这样零构建依赖、改完直接生效。88MB 的运行时压完只剩 34MB，正常分享没问题。

**为什么 zip 是手写的**（`_dev/zipwrite.mjs`）：Windows 自带的 `Compress-Archive` 和 .NET 的
`ZipFile.CreateFromDirectory` 都会用**反斜杠**当路径分隔符，**还都不写目录条目**，而且 PowerShell 5.1
下用系统代码页写文件名（中文名在别的系统上会乱码）。这样打出来的包在 Windows 上解压看着一切正常，
到了 macOS / Linux 上会解成一坨平铺的、名字里带反斜杠的怪文件。现在用 Node 自带的
`zlib.deflateRawSync` + `zlib.crc32` 手写 zip：条目名一律 `/`、目录以 `/` 结尾并带 MS-DOS 目录位、
文件名声明 UTF-8（bit 11）、`.sh` / `.command` 给 0755 而 `bin/node.exe` 明确压成 0644
（否则 Mac 上会误判成可执行，然后试着执行一个 Windows 程序）。

### 发到 GitHub Releases

```bash
$env:GH_TOKEN = 'ghp_xxx'      # 需要 repo 权限；别把 token 写进代码
node _dev/release.mjs
```

版本号从 `server.mjs` 的 `version` 读，正文用仓库根目录的 `RELEASE-<版本>.md`，
附件直接取 `dist/` 里刚打好的包。参数：`--tag v0.3.0` 指定标签、`--recreate` 已存在就删掉重建。

如果这个版本还没打标签，先手动打一次再跑：

```bash
git tag -a v0.3.0 -m "v0.3.0 — 一句话说明" && git push origin v0.3.0
```

> ⚠️ **附件名只能用 ASCII。** GitHub 的 release asset 接口会把文件名里的非 ASCII 字符
> **静默丢掉**——不报错、HTTP 200，名字却变了。实测 `probe-测试.zip` 存成 `probe-.zip`，
> 先做 percent-encoding 也一样，编码两次更惨（`probe-.E6.B5.8B.E8.AF.95.zip`）。
> 所以 `release.mjs` 上传时统一换成 `music-overlap-<版本>-portable.zip`，
> **解压出来的目录仍然是中文的**「音乐重合度-便携版」。

直连即可。网络需要代理时：

```bash
set MUSIC_PROXY=127.0.0.1:7890    # cmd
$env:MUSIC_PROXY="127.0.0.1:7890" # PowerShell
export MUSIC_PROXY=127.0.0.1:7890 # macOS / Linux
node server.mjs
```

### 改完代码怎么验

**不需要网络也不需要起服务的一道**（最快的回归，统计口径的边界都在这）：

```
node _dev/compare-check.mjs     # 26 项：跨平台并集 / 截断 / ID 命中但无详情 / 缺歌手 / 分母同源
```

它靠 `compare()` 的 deps 注入口喂假数据进来，所以不碰网络。**改了 `compare()` 必须先跑这个。**

再起服务（比如 `node server.mjs 8799`），开另一个窗口跑：

```
node _dev/api-check.mjs 8799    # 接口层，67 项断言，几秒跑完
set BASE=http://127.0.0.1:8799  # PowerShell: $env:BASE="http://127.0.0.1:8799"
node "_dev/多平台自检.mjs"       # 界面层，47 项：三平台 / 跨平台 / 酷狗降级 / 播放器
node "_dev/新界面自检.mjs"       # 界面回归，43 项：四视图 / 播放控制 / 搜索过滤
```

全部绿是提交前的底线。界面层的两个脚本用系统自带的 Edge 无头模式真实点一遍，
并把每一步的截图写到 `_dev/`（截图里含真实歌单名与头像，所以 `_dev/shot-*.png`
和自检记录都在 `.gitignore` 里，不上传）。

改到打包那块（`zipwrite.mjs` / `build-portable.mjs`）再补两刀——**这两个要设 `PYTHON_EXE`
指向真的 Python**（WindowsApps 里那个是微软商店的假桩，会静默不干活）：

```
node _dev/build-portable.mjs          # 先重新打包
set PYTHON_EXE=C:\path\to\python.exe  # PowerShell: $env:PYTHON_EXE="..."
node _dev/zip-check.mjs               # 22 项：验写入器（自己造小样本，跑得快）
node _dev/zip-verify-dist.mjs         # 23 项：验真实产物（88MB 那个 zip）
node _dev/probe-launcher-sh.mjs       # 8 项：验启动器「选哪个 node」的四条分支
```

为什么要用两种完全独立的解析器来回验：**单一解压器会骗人**。Python 的 `zipfile` 在 Windows 上
会自动把反斜杠归一化成正斜杠，所以最初的坏包解压看着一切正常；而 .NET 又只认属性位不看条目名。
只有直接读中央目录的原始字节才是没有立场的证据。

`probe-launcher-sh.mjs` 要说清它验的是什么：它把 `启动.sh` 里那段判断原样抠出来、机械翻译成
Python 再跑，所以验的是**分支逻辑对不对**（四种情况各选了哪个 node、该说的话说了没有），
**不是**在真的 sh 里跑过。这台开发机没有 sh / bash / WSL，所以 `启动.sh` 的真实执行只能在
Mac 或 Linux 上才算验过；能在这里板上钉钉的只有字节级事实——纯 LF、首行 shebang、
`bin/node.exe` 在 zip 里是 0644（这些由 `zip-verify-dist.mjs` 负责）。

## 隐私

- 请求直接发往各平台自己的域名，本工具没有任何后端服务器
- 页面下方的可选凭证只用于请求对应平台，**不写入任何文件**；它存在内存里，关掉服务就没了
- 代码不做任何数据上报

### 本地服务做到了哪一步

服务只监听 `127.0.0.1`，还挡了一层**本机其他网页**：所有 POST 只接受 `application/json`。
普通 `<form>` 提交发不出这个 Content-Type，跨站 JS 想发就得先过 CORS 预检，而本服务从不回
CORS 头 —— 否则你在浏览器里随手打开的任意网页，都能往 `127.0.0.1:8787` 发个表单把凭证改掉。

**没有做** Host / Origin 校验：浏览器管的域名不构成安全边界，Host 头普通 JS 又改不了，
加了只是看着安全。真要防，靠的是上面那条。
